# 三分钟项目讲解

按买方问题、设计决定和验证结果讲解。先看[案例](case-study.md)，按[证据索引](evidence-map.md)核对实现与业务结果。

## 第一分钟：业务任务

说明公司希望承接海外访问，重点买方要完成的任务是判断供应商、查找材料、比较资料并咨询。用README的流程图解释从产品/应用/企业证据到统一表单的路径。

明确三种不同产物：完整业务站的本地版本、这个公开案例、精选代码的离线演示。不要把公开案例库说成完整网站源码。

## 第二分钟：一个值得追问的决定

运行 `npm run demo`，依次看未配置、200但无保存回执、匹配保存回执三种结果。解释为什么“界面看起来提交了”不足以证明业务能找回请求，以及失败输入保留、稳定提交ID、保存和通知分离各自解决什么问题。

结果来自内存模拟，不是真发邮件。实际生产收件需要另行接通和验收。

## 第三分钟：范围和复盘

说明首期为什么使用统一表单和人工跟进，而没有优先堆叠CRM与AI客服。多语实现、技术资料与内容审核都是持续工作；页面数不能代替真实用户任务成功或商业结果。

可以准备回答：

- 经销商优先的依据是什么？哪些已确认，哪些仍是假设？
- 为什么先提供资料上下文，再让用户描述需求？
- 资料留资带来的摩擦如何衡量？是否一定要所有资料都设门槛？
- AI辅助生成了哪些部分？你能独立解释和修改哪个规则？
- 如果访问有了但有效询盘很少，如何区分流量、内容、表单和销售承接问题？

下一轮验证优先使用少量真实业务/买方任务测试与生产收件联调，记录卡点和改动，不虚构转化收益。
