## 个人贡献与工具贡献

| 可讲述的工作 | 如何理解 |
| --- | --- |
| 提供业务目标、资料与评审意见，参与范围讨论并推动迭代 | 以具体问题和改动说明职责；不等于正式PM职称或带领开发团队 |
| 判断公开内容、买方路径和首期承接需求 | 说明业务要求、自己的输入与AI建议分别来自哪里 |
| AI辅助代码、文档与测试 | 需能解释和复核；生成产物不能自动证明个人已独立掌握全部实现 |

## 阅读顺序

先看[案例](case-study.md)理解业务和取舍，再按W02–W04运行代码核对关键规则。[实现范围](implementation-scope.md)列出原模块的脱敏适配，正式运行依赖见[上线边界](measurement-and-launch.md)。整理日期不改变历史验收日期。
