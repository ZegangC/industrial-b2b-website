# 精简PRD：浏览、咨询与资料申请

2026-10-15 根据已有实现与需求记录整理。当前内容是对外摘要，不复制原始公司资料。

## 用户任务与范围

| 任务 | 核心能力 | 取舍 |
| --- | --- | --- |
| 判断是否值得进一步了解供应商 | 企业资料与可追溯的证据 | 缺审核材料时不编造认证或效果 |
| 找到适用方向 | 产品族、应用筛选、主推对比 | 导航分类不代表具体配方适用保证 |
| 获取技术资料或讨论样品 | 多入口、统一表单、文档匹配 | 资料与产品一致，缺配置明确不可用 |
| 销售理解并跟进需求 | 需求、语言、来源与稳定提交ID | 首期不自建CRM，不把匿名访问当联系人 |

首期优先级是业务路径、可靠收件与内容事实。多语运维和内容审核持续推进；AI客服、复杂内部管理和更多跟踪能力后续另行评估。

## 提交数据

必填姓名、工作联系邮箱、公司、国家/市场、需求及隐私告知确认。免费邮箱不自动排除。产品、应用、角色、数量、电话为业务上下文字段，按实际需要使用；不以填表直接判定商机有效。

来源只接收允许的页面路径与简单活动标签，不转发任意URL查询参数。提交ID用于重试去重；持久化去重依赖最终接收服务，前端附带ID本身不构成去重保证。

## 验收场景

| 场景 | 应有行为 | 公开验证范围 |
| --- | --- | --- |
| 非法枚举、缺字段或过长需求 | 拒绝并返回字段错误 | validateInquiry及测试 |
| 页面来源包含任意邮箱查询参数 | 不纳入允许的来源字段 | 输入过滤测试 |
| 未配置接收服务 | 不调用接收端，不报告成功 | 演示与测试 |
| 接收端200但无匹配保存回执 | 不报告成功 | 演示与测试 |
| stored=true且ID匹配 | 接收规则返回成功 | 内存模拟；不证明业务邮箱送达 |
| 同ID同内容本地TDS重试 | 本地保存幂等；内容变化拒绝 | 临时目录测试 |
| 下载签名、文档或有效期不符 | 拒绝授权 | 签名规则测试 |
| 生产环境携带本地预览开关 | 本地模式不能启用 | 测试 |

## 上线依赖

正式域名与托管、持久化接收与通知、反机器人及限流、文件/密钥私有管理、主体与资料审核、语种审校、隐私流程和销售负责人。完整HTTP路由、UI与服务联调不在公开模块测试覆盖范围内。
